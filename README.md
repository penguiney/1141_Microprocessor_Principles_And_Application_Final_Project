## 系統功能與原理說明) :
使用 PIC18F4520 微控制器，結合 KY-023P 類比搖桿、433MHz RF 無線模組以及兩種馬達，實現遠端操控四輪車。透過 ADC 取得方向與速度輸入，並將資料打包成封包，433MHz RF TX將數位訊號轉成高頻無線電波訊號發射到空中，再由車體端的433MHz RF RX接收。PIC18F4520接收指令後，以 PWM 控制直流馬達驅動後輪，並控制伺服馬達實現前輪轉向，完成前進、後退與左右轉動作。

## 系統使用環境及對象

本系統為一套以PIC18F4520 微控制器為核心之無線遙控車系統，主要應用於室內或半開放空間之短距離無線控制情境。系統使用 PS2 類比搖桿作為人機介面，使用者可透過搖桿即時輸入前進、後退、左轉、右轉及斜向共8個方向控制指令，並經由 433 MHz RF 發射與接收模組進行無線資料傳輸，達成對遙控車運動方向之即時控制。

### 使用環境
本系統適合於以下使用環境：
- 室內環境：如實驗室、教室、走廊等，環境中無大量金屬遮蔽物與強烈干擾，能確保無線通訊之穩定性。
- 短距離無線控制場景：在視距範圍內進行操作，433 MHz 無線模組可提供足夠的通訊距離以滿足一般教學與展示需求。
- 教育與展示用途：適合用於嵌入式系統、微控制器應用與無線通訊相關課程之實驗或成果展示。


### 使用對象
本系統之主要使用對象包含：
- 修習嵌入式系統或微控制器相關課程之學生：可藉由實作理解 PIC18F4520 在類比訊號讀取、外部中斷與無線通訊控制上的應用。
- 課程專題與初階系統開發者：系統架構模組化，適合用於基礎無線控制與控制邏輯設計之學習。
- 教學與展示用途之操作人員：透過搖桿操作遙控車，能直觀呈現人機介面、無線傳輸與車輛控制之整合應用。

## 系統開發工具、材料及技術
### 開發工具：
- 使用MPLAB作為主要主要開發工具

### 使用材料：
- PIC18F4520 * 2，用於控制狀態機，分為發送端（控制器）與接收端（車體）
- KY-023P * 1，用於ADC輸入，將收到的訊號送給PIC18處理
- 433MHz RF TX + 433MHz RF RX，用於無線訊號傳輸
- MG996 * 2，使用 CCP1/CCP2 控制前後移動
- SG90 * 1，使用 Timer3 來實做 PWM，讓 SG90 改變角度，實現轉向功能
- LED燈 * 9，用於車輛狀態指示
- 紙盒、竹筷、膠帶，用於製作車身主要材料

### 使用技術：
- Interrupt，發送端偵測ADC輸入，當輸入改變時觸發interrupt並發送訊號給接收端。接收端接收到發送端所發送的訊號時，使用interrupt改變馬達方向/轉速

- Timer，控制訊號發送間隔及頻率，另外，由於PIC18F4520內建的PWM有
限，我們額外使用 Timer3 實作 PWM 來控制轉向，以20ms作為一個循環，每個循環進中斷兩次，一次將RA0調高，一次調低，每次中斷後填入新的tmr3的值來達到控制duty cycle的目的。
若在調高訊號時設定TMR3為65536 - 375(在1MHz下持續1.5ms)，調低訊號時則設定TMR3為65536 - (5000 - 375) (在1MHz下持續20 - 1.5ms)

        TMR3中斷，RA0 = 1 --------1.5ms------> TMR3中斷，RA0 = 0 --------18.5ms------> TMR3中斷，RA0 = 1 ...

- PWM，當interrupt發生時，控制 MG996 及 SG90 以實現基本車輛移動

- ADC，KY-023P 作為主要輸入，每當有訊號改變時，觸發發送端interrupt

- 433MHz 無線訊號傳輸
    封包內一共47bits，有17bits的preemble，6bits的sync_word，8bits的celerate，8bits的direction，剩下其他8bits尚未實作
    
    - 發送端：以timer1計時，每3ms發送1bit訊號，每150ms更新封包資料，重送一次訊號。
    
    - 接收端：以timer1計時，每3ms接收1bit訊號，以finite state machine紀錄接收封包的狀態：

        state 0為preemble對齊，輪流接收010101...的訊號，在收到重複的電位(...011)以前若是對齊6個以上的訊號則進入state 1，反之重頭開始。
        
        state 1為sync訊號驗證，與preemble不同，必須要6個訊號都正確讀取才會進入下一個state，反之回到state 0，等待下一個封包。
        
        
        state 2為資料接收。將2bits的訊號拉長成8bits來提高容錯率，舉例，若發送方送出8個0作為-1，接收端只要接收到6個以上的0就視為-1，結束以後回到state 0。
     

## 周邊接口或 Library 及 API 使用說明

### Car Control API 使用文件

本文件說明車輛方向（轉向）與速度（前進 / 停止 / 後退）控制之 API 使用方式，適用於使用 PWM 控制伺服馬達與直流馬達的自走車系統。

---

### 1. car_direction
```c=
void car_direction(int direction);
````

### 功能說明

控制車輛的轉向角度，透過設定伺服馬達的 PWM ticks 值，使車輛向左、向右或回正。

### direction 定義

| 值  | 行為     |
| -- | ------ |
| 1  | 向右轉    |
| 0  | 回正（直行） |
| -1 | 向左轉    |

### 行為細節

* 伺服馬達可接受 PWM ticks 範圍：`250 ~ 500`
* 車輛實際使用範圍：`300 ~ 450`
* 採用「直接定位」方式設定轉向角度

```c=
if(direction == 1)  direction_ticks = 450; // 右轉
if(direction == 0)  direction_ticks = 375; // 回正
if(direction == -1) direction_ticks = 300; // 左轉
```
---
### 2. car_speed
```c=
void car_speed(int speed);
```

### 功能說明

控制車輛的行進方向（前進 / 停止 / 後退），透過 PWM duty 設定左右輪馬達轉速與方向。

### speed 定義

| 值  | 行為 |
| -- | -- |
| 1  | 前進 |
| 0  | 停止 |
| -1 | 後退 |

### 前進（speed == 1）

```c=
// clockwise (~2.0 ms)
PWM_set_duty(70, 107);
PWM_set_duty(90, 100);
/*
 * 馬達順時針旋轉
 * PWM pulse 約為 2.0 ms
 * 左右輪 duty 不同，用於修正直線偏移
 */
```


### 停止（speed == 0）

```c=
// stop (~1.5 ms)
PWM_set_duty(95, 96);
/*
 * PWM pulse 約為 1.5 ms
 * 馬達停止
 * /
```



### 後退（speed == -1）

```c=
// counterclockwise (~1.0 ms)
PWM_set_duty(110, 70);
PWM_set_duty(100, 85);
/*
 * 馬達逆時針旋轉
 * PWM pulse 約為 1.0 ms
 * /
```

---
### 3. 使用範例

```c=
// 向右轉並前進
car_direction(1);
car_speed(1);

// 回正並停止
car_direction(0);
car_speed(0);

// 向左倒退
car_direction(-1);
car_speed(-1);
```

## 遇到的困難及如何解決
### 困難點一：
- 原本預計使用nrf24L01完成通訊 ，但是數次嘗試以後依舊無法通訊，最後只好使用433MHZ TX RX模組，而433MHZ TX RX模組只有1bit的數位輸出，沒有濾波、也沒有編碼解碼，需要自己包裝封包、調整訊號。


### 困難點二：
- 沒有用後輪軸連結兩顆後輪，而是使用兩顆正轉和反轉的馬達分別控制左輪和右輪，占用掉了PIC18F裡的CCP1和CCP2，於是只好用一個數位PIN腳(RA0)來模擬PWM訊號，以Timer3控制高低的時機。


### 困難點三：
- 組裝完整台車後才發現MG996R相當吃電，起步或撞到東西時時容易造成整台車掉電卡住，後來給每個馬達自己分配了一條TTL線才好轉，並且MG996R啟動時有不小的雜訊，需要將通信模組遠離車體以免受干擾。
